## 新增待修复：R5 · P2 迟到的编辑完成回调清空下一账号的新草稿

**触发与结果**：A 在频道编辑自己的消息，服务端已执行 PATCH，测试屏障暂扣成功响应。A 在同一 SPA 中退出，B 登录并打开该频道，输入新草稿 `R5_BOB_UNSENT_DRAFT`。释放 A 的编辑响应后，B 的输入栏变成空串，未发送的草稿丢失。Chromium 与 WebKit 均在“草稿必须保留”的断言失败，实际收到 `""`，持续到 10 秒断言超时。

这是客户端的迟到回调造成的数据丢失。本轮没有在这个场景观察到 A 的旧消息进入 B 的时间线，也不将其误报为原 R3 的正文泄露仍未修复。

**位置与根因**：

- `apps/web/src/features/message-actions/actions.ts:52–53`：`editMessage` 调用 `engine.ingestMessage(envelope, ticket)` 后丢弃返回值，即使引擎因旧账号/旧成员关系拒绝响应，仍返回 `true`。
- `apps/web/src/features/composer/composer.tsx:95–100`：旧组件的异步 `send()` 恢复执行，见到 `true` 后调用旧闭包 `leaveMode()`；组件已卸载不会取消这个 Promise 后续逻辑。
- `apps/web/src/features/composer/composer.tsx:83–87` 与 `apps/web/src/lib/sync/compose.ts:76–79`：`endCompose(id, oldMembershipId)` 找不到旧成员关系的模式时仍无条件删除该会话当前模式，随后旧闭包用 `setDraft(id, '')` 清空全局草稿。按会话 id 保存的新账号状态因此被旧回调修改。

**证据**：

- `.test-runs/m2b-recheck/adjacent.spec.ts`：真实 API/worker、生产构建、同页账号切换、真实编辑操作；不是直接调用内部 store 模拟 UI。
- `.test-runs/m2b-recheck/adjacent.log`：两个引擎均在最终草稿断言失败，屏障前的新草稿断言成功。
- `.test-runs/m2b-recheck/browser-results/`：每个引擎各自的失败截图、错误上下文与 `trace.zip`；`r5-after.png` 是最后一个引擎释放屏障后的额外截图。

```bash
bun run --cwd apps/web e2e --config ../../.test-runs/m2b-recheck/playwright.config.ts
```

**修复要求与复验条件**：

1. 编辑完成后对 UI/store 的副作用也必须受请求身份边界约束；引擎拒绝旧响应时，不能向 Composer 返回“可完成当前编辑”。只给缓存合并加凭据不够。
2. 完成编辑必须对应发起时那一次编辑：账号、成员关系、编辑模式以及期间的新输入发生变化时，旧完成回调不能清理当前模式或覆盖新草稿。同一成员关系下，等待保存期间取消旧编辑、开始另一条编辑的情况也要保护。
3. `endCompose` 对不匹配的成员关系应当无副作用，不能仅因找不到旧 stash 就清空新模式；草稿写入也要核对当前所属状态。
4. 将该屏障用例迁入正式回归；覆盖跨账号、退出重入、同成员关系取消/切换编辑，以及正常保存恢复原 stash。跨账号已经在两个引擎复现；后三种是修复应补的相邻回归，本次没有声称均已做浏览器复现。

### 同类的其他「回答之后的界面收尾」（Claude，2026-10-06，你让我一并处理）

R5 的根因不只出现在编辑：D-171 的凭据只管住了缓存的合并，回答回来之后顺手做的界面收尾（跳转、提示、结束会话）没有管，而提示和跳转是全局的，不随组件卸载。对其他屏幕的静态检查发现 14 处会话类写请求和 3 处设置类写请求有同样的问题，**旧代码上用浏览器复现了九种**（新建群组、退出、归档、解除封禁、改成员、隐藏私信、频道发现里加入、恢复归档、设置里改时区）：后一个账号被带到前一个账号刚建的群里或拉回首页，提示里出现前一个账号的会话名、用户名。还有一处更重的：设置里「退出所有设备」成功后直接 `endSession`，迟到的话会结束后一个账号的客户端会话。

做法见 [D-174](12-decisions.md)：引擎新增 `isCurrent(ticket)`（同一次登录会话、同一个成员关系；比缓存宽，改密码换登录世代不算换人），屏幕的写请求一律经 `forScreen`，不是发起人时回答和失败都是 null，屏幕什么也不做；返回类型带 null，用到回答的地方漏了判断编译不过。一条读源码的守卫测试 `features/screen-writes.test.ts` 守住这条约定。回归：`for-screen.test.ts`、`engine.test.ts` 的 `isCurrent` 一组、守卫测试、`e2e/late-effects.spec.ts` 九条（Chromium 与 WebKit）。限制见 D-174 与 PROGRESS。
