## 2. 独立复现与修复

### R1：通知投影保留了撤回和退群前的内容

原通知测试在撤回后重新加载页面，没覆盖已经打开的面板。去掉重新加载，并增加退群用例后，两条 Chromium 用例均失败：撤回后的旧摘要仍在；退出后群名、发送者和摘要仍在。

通知行的 `version` 只随已读状态变，不代表被引用消息或成员权限的版本。现将两者分开：来源变化同步清除投影；请求带投影世代和请求次序，旧回答不能把内容放回来；新授权读取更新投影，同时保留较新的已读版本。个人日志和标读回答只合并行状态，不直接安装可能过时的来源。刷新覆盖全部已加载页面，过期条目与降权后的预算通知也从快照删除。消息提示、同步补齐、会话重置和个人权限变化均接入来源失效通知。

正式回归包括持续打开的面板撤回、退群、迟到的真实读取回答，以及旧分页来源的撤回。`notifications-before.log` 与 `notifications-before-results/` 保留首次失败；分页夹具初次触发真实发送限流，改为四个会话各自低于原限流，不改应用限流或断言。

首轮全量另发现 WebKit 点击后只关面板、不跳转：失效提示临时清除了来源，点击使用了渲染时的「无目标」。用「鼠标按下后，另一设备标读；暂扣来源重读，再抬起鼠标」正式复现，Chromium 与 WebKit 都失败。现无目标的点击重新读取当前投影，复核原登录及最近点击意图，在当前回合再取来源后才跳转；对失效或失败的读取不复用旧目标。另补迟到点击读回时换人的草稿/页面隔离。`notification-click-before.log` 与对应结果目录保留两条失败。

### R2：推送操作的身份跨越了异步等待

三条单元复现确认：浏览器权限返回前换人、读取订阅期间换人、删除订阅期间换人，旧操作可以继续写身份、登记新账号订阅或退订新账号。现从操作开始即固定引擎票据，在浏览器与 HTTP 的每次异步等待之后复核；Worker 消息发送和注销清理也受原登录世代约束。迟到的旧账号推送只丢弃载荷，不删除新账号订阅。

未知身份也不能证明浏览器订阅属于旧账号：真实 Worker 独立探针在身份尚未到达时记录到一次退订。现其他账号的载荷始终只丢弃，退订由页面的世代受控操作和服务端的会话绑定负责；身份消息在途时不猜测归属。正式回归位于 `worker-handoff.spec.ts`，首次结果见 `unknown-worker-before.json`；原独立探针修复后退订为 0，见 `unknown-worker-after.json`。

另用真实 Worker 独立探针复现：未等待原注销消息完成就切换身份后，前一个账号已显示的通知仍有一条。现身份更新、注销与显示推送按顺序执行，新身份本身会关闭其他账号的已显示通知，保留本账号的通知。`sw-handoff-before.json` 与探针源文件保留首次结果；原探针修复后残留为 0，见 `sw-handoff-after.json`；正式回归验证已显示及在途通知的交接和原 AT-17 路径。

继续检查浏览器自动续订时，真实 Worker 独立探针与正式浏览器回归都复现「续订等待期间换人，旧操作仍登记一次」；真实数据库两条回归另确认，旧请求可以通过新账号 Cookie 转移绑定，失效 Cookie 的 Worker 回答也会携带删除 Cookie 的响应头。现续订返回后复核原身份/安装；页面登记与 Worker 续订都提交 `expectedUserId`，服务端与当前 principal 不符即 403；推送接口沿用附件接口的只读认证模式，不刷新或删除 Cookie，迟到的 Worker 回答不会改变后来的登录。接口仍按有效会话鉴权，其他页面的身份读取负责滚动刷新和失效清理。`renewal-before.json`、`renewal-formal-before.log`、`renewal-bindings-before.log` 保留首次失败。修复后完整推送集成 **49/49、453 断言** 通过，OpenAPI 快照经生成及普通比较两次通过；首轮新测试把返回包装直接传入错误码助手的 fixture/typecheck 失败也保留，修正后通过。

### R3：离线清理的时点与容量上限不完整

四条单元复现失败：写入未执行容量上限、长期开着的页面写入时未清过期项、旧账号的磁盘读取能删新账号记录、清理旧成员记录期间换人后仍恢复旧待发项。现写入后也执行原 7 天 / 50 MiB 策略；磁盘读取、清理和恢复均带原作用域及操作世代检查。来源变了之后不清别人的记录，也不恢复旧账号待发消息。`offline-before.log` 保留首次失败；正式回归在 `offline/store.test.ts`、`persistence.test.ts`。

### R4：推送出口的总期限与响应头上限

独立无网探针确认，DNS 不回答时即使传输期限设为 25 ms，1.5 秒之后仍在等待。正式本地 TLS 回归又确认，超过 16 KiB、但带完整结束标记的响应头会被接受。现从 DNS 前开始共享同一个期限；迟到的解析结果不再开启连接；完整响应头与未结束响应头都受原 16 KiB 上限。`dns-before.log` 与 `transport-before-formal.log` 保留首次失败；修复后正式传输回归 14/14，原独立探针 1/1。没有访问真实厂商推送服务。

### R5：旧推送回执更新或删除了新账号的绑定

真实数据库中，在发送期间把同一安装的端点从 Bob 转给 Erin，再返回原请求的 delivered / gone / rejected / 第五次 rejected。四条正式回归全部失败：旧成功写入新账号的成功时间；旧失效或第五次拒绝删除新绑定；旧拒绝给新账号加失败计数。现每一次清理和回执更新都在 SQL 中匹配原 id、账号、登录会话与绑定版本，换绑定后旧回执的更新/删除不生效。`binding-before.log` 保留四条失败；完整推送集成修复后 47/47、444 断言通过。没有把测试订阅的认证值写入失败差异。
