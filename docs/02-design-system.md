# 02 设计规范（Apple Liquid Glass 风格，桌面优先）

> 设计阶段 D 已在 **2026-10-02** 定稿：用户在 D4 确认了视觉和交互（D-113），确认的值已并入下面的第 2 到 7 节。依据、实测数据和没有验证的事见[第 10 节](#10-d-阶段成果2026-10-02d4-已确认)。M1b（2026-10-03）已把第一批组件落到 Storybook，见第 8 节。
> 可点击原型在 `design/prototype/`，只是评审用的参考实现；它和本文冲突时以本文为准。令牌的数据源是 `design/prototype/tools/tokens.mjs`，改令牌要先过 `bun run design:contrast`（D-111）。

## 1. 风格来源

- **Apple Liquid Glass**：2025 年随 iOS 26 / macOS 26 推出。2026 年 WWDC（iOS 27 / macOS 27）又做了修正，重点放在**可读性**上：
  - 玻璃更善于"化开"背后复杂的内容；
  - 边缘加深、高光更亮；
  - macOS 工具栏回到统一的磨砂效果；
  - 系统设置里新增透明度滑块，可在"清透"到"着色"之间调节。
- **布局与质感的参考 App**：macOS 的「信息」「邮件」「备忘录」。
- **原则**：
  - 内容优先：界面要退后，让消息成为主角。
  - 清晰：层级明确，文字始终可读。
  - 层次：导航层"浮"在内容层之上。

### 法律与素材红线
- **不打包 SF Pro / SF Mono 字体文件，也不使用 SF Symbols。** Apple 的授权只允许在 Apple 平台上使用它们。除了 Inter（OFL 协议，可以自托管，见 4.3）之外，我们只在 CSS 中引用系统字体名，由用户设备上已安装的字体来显示。
- 不使用 Apple 的商标、Logo 和图标，不照搬 Apple App 的界面素材。我们借鉴的是设计语言，应用图标自行设计。

### D1 方向要点（2026-10-02，原型据此实现）

不收集 Apple 的界面截图作为情绪板（红线），改用下面这些可检验的要点：

- **三层结构**：壁纸层（淡渐变加几块强调色色块）、内容层（实底）、导航层（玻璃）。侧栏、内容区、Inspector 是三块浮在壁纸上的圆角面板，彼此留 8px，外层圆角 16px。
- **玻璃的材质分三种**：只浮在壁纸上的（侧栏，随透明度档位）、承载文字的（工具栏、输入栏、菜单、弹层，有不透明度下限）、放在实底上的（审批卡、悬停工具条，不开模糊）。见第 2 节。
- **可读性高于通透**：文字对比度先于玻璃效果。2026 年的修正方向（边缘加深、高光更亮、工具栏统一磨砂）也是这个取向。
- **状态不只靠颜色**：在线用实心点、离开用缺一角的点、离线用空心圈；选中的会话有左侧色条；开关打开时里面有勾；密码规则用图标加文字。
- **同屏最多 4 个模糊层**：侧栏、工具栏、输入栏各一个，再加一个弹出的层。打开模态层时，被遮住的工具栏和输入栏去掉模糊。
- **圆角同心，气泡带尾巴**：组内相邻一侧 6px，每组最后一个气泡带尾巴；Chromium 上面板和玻璃再加 `corner-shape: squircle`，其他浏览器退回普通圆角。

## 2. 玻璃材质的使用规则

- 只有**导航层**使用玻璃：侧边栏、顶部工具栏、底部输入栏、弹出菜单、弹层（sheet）、⌘K 命令面板、分段控件。
- **内容层保持实底**：消息列表、消息气泡、长文本区域都**不**用玻璃，保证可读性。
- 应用背景铺一层淡淡的渐变（带一点强调色），让侧边栏的玻璃"有东西可透"。壁纸上的强调色色块用柔边渐变，每层不超过 30%（浅）/ 34%（深）；侧栏玻璃的对比度检查以它为前提。
- **玻璃分三种材质**（D-109，D4 确认）：

| 材质 | 用在哪里 | 不透明度 | 模糊 |
|---|---|---|---|
| `.glass` | 只浮在壁纸上、背后颜色已知的层：侧栏 | 随下面的四档；"着色"档叠加强调色调 | 随档位 |
| `.glass-text` | 承载文字、背后可能是任意内容的层：工具栏、输入栏、菜单、弹层、命令面板、设置面板 | 取所选档位和下限中较大的一个：下限 90%（浅）/ 88%（深）。不带强调色调，"着色"档改为淡淡的强调色光边 | 随档位 |
| `.glass-lite` | 放在实底上的小件：审批卡、悬停工具条、"回到最新"按钮 | 同 `.glass-text` | 不开模糊 |

- **为什么有下限**：背后是纯黑图片时，浅色玻璃上的主文字 / 次要文字 / 占位文字，清透 45% 只有 4.06 / 1.50 / 1.27:1，标准 62% 为 6.95 / 2.66 / 2.25:1，着色 80% 的次要文字 4.44:1 仍不够；深色玻璃在纯白图片上同理。下限由脚本按黑白两个极端反推（留 4.6:1 的余量）。所以三个半透明档位**只影响侧栏**；要更通透，必须先放宽下限，代价是个别背景下文字不达标。
- 用户可以在设置里调节透明度，分四档（只作用于 `.glass`）：

| 档位 | 背景不透明度 | 模糊 | 说明 |
|---|---|---|---|
| 清透 | 45% | 20px | 最有玻璃感 |
| 标准（默认） | 62% | 24px | |
| 着色 | 80% | 28px | 叠加强调色调 |
| 不透明 | 100% | 无 | 浏览器报告系统开启了"减少透明度"（`prefers-reduced-transparency: reduce`）时强制使用，此时**所有**玻璃都变成不透明、不模糊、不带色调。不支持这个媒体查询的浏览器，由用户在设置里手动选择 |

- **边缘处理**（参照 2026 年的修正）：外侧 1px 加深描边，内侧顶部 1px 高光，再加柔和的投影。
- **性能**：`backdrop-filter` 最多在同一屏同时出现 4 处（侧栏、工具栏、输入栏各一个，再加一个弹出的层）。打开模态层（命令面板、设置、对话框）时，被遮住的工具栏和输入栏去掉模糊（它们已不低于 88% 不透明，几乎看不出区别）；悬停工具条、审批卡、"回到最新"不开模糊（D-110）。折射类的 SVG 滤镜特效只用于少数装饰位置，而且要能关掉。

## 3. 桌面布局

```
┌─────────────┬──────────────────────────────────────┬──────────────┐
│ Sidebar     │ Toolbar (glass): title · members · actions         │
│ (glass)     ├──────────────────────────────────────┤ Inspector    │
│ search ⌘K   │                                      │ (toggle)     │
│ pinned      │   Timeline (solid, virtualized)      │ [Details |   │
│ channels    │   max content width 860px            │  Assistant]  │
│ groups      │                                      │              │
│ DMs         │                                      │              │
│ agent chats │  ╭ Composer (floating glass) ──────╮ │              │
│ ─────────── │  │ + 😊 ✦  message…            ⬆ │ │              │
│ me · status │  ╰─────────────────────────────────╯ │              │
└─────────────┴──────────────────────────────────────┴──────────────┘
   280px (240–360, draggable)                             320px
```

**浮动面板**（D4 确认）：侧栏、内容区、Inspector 是三块浮在壁纸上的圆角面板，彼此留 8px，外层圆角 16px（`--radius-window`）；上图只表示内容的排布。

**侧边栏**
- 最上面是搜索框（提示 ⌘K）。
- 下面依次是：置顶、频道、群组、私信、助手（Agent 会话）。
- 每一项显示：头像或图标、名称、最后一条消息预览（可以切换为紧凑模式不显示）、时间、未读徽标（强调色胶囊）、@提及标记、免打扰图标。
- 选中的会话用强调色 8% 的底色，左边加 3px 色条（不只靠颜色；16% 的底色会让深色黄、浅色石墨下的预览文字低于 4.5:1）。
- 侧栏宽度可以拖动；拖动条的可点击区域 28px 宽，延伸进内容区空白的左边距。
- 最底部是当前用户卡片：头像带在线状态点，旁边是通知铃铛（M6，带未读数）和设置按钮。
- 分组末尾的"更多"菜单里有"已归档"，列出我是群主的已归档会话，可以在那里恢复。

**工具栏**
- 左侧是会话头像和名称；副标题在群组里显示成员数，在私信里显示对方的在线状态。
- 右侧是三个按钮：成员、助手面板、更多。

**时间线**：消息内容居中，最大宽度 860px；每个气泡最宽不超过时间线的 65%。

**输入栏**
- 悬浮在底部的玻璃胶囊，距离边缘 16px。输入内容变多时自动长高，最高占窗口的 40%。
- 按钮依次是：附件、emoji、@助手（✦ 图标）、发送。发送键是强调色圆形按钮，输入为空时禁用。
- 输入法组字期间，回车只确认候选词，不发送；组字结束后按回车才发送（D-050）。

**Inspector（右侧面板）**
- 顶部是分段控件 [详情 | 助手]。
- 详情页显示：成员列表、共享文件（M3 起）、会话设置；管理员还能看到封禁名单。
- 开启了助手的会话，在设置里显示一行提示："@助手 时，最近的消息会发送给 AI 服务处理。"
- 助手页就是 Agent 面板，见第 6 节。

**宽度适配**
- 1024–1279px：Inspector 从右侧以浮层形式弹出，不挤占时间线。
- 768–1023 CSS px：侧栏折叠，Inspector 弹层；低于 768 至 320 CSS px：单栏时间线，导航抽屉，输入栏自动换行。桌面 400% 缩放不能产生整页横向滚动；代码块/表格可独立横滚。手机专用交互仍在 v1.1。

**空状态**：没有选中会话时，显示欢迎页和常用快捷键。

## 4. 设计令牌（D4 确认）

以 Tailwind v4 的 `@theme` 变量实现，颜色以 sRGB 的十六进制或 `rgb()` 书写（D 阶段的令牌表即如此，对比度脚本按 sRGB 计算；这里原先写的 OKLCH 没有采用），深浅模式通过 `light-dark()` 切换。数据源是 `apps/web/src/design/tokens.ts`（M1b 起，D-114）：它生成运行时 CSS 和 Tailwind 主题，并驱动 `bun run design:contrast`（3018 组对比度检查，包含在 `bun run check` 里）；改令牌必须先过它（D-111）。原型里的 `tools/tokens.mjs` 只是转出口。

D-092将次要/占位色改为不透明值；适用浅色背景为#FFFFFF/#F2F2F7/#E9E9EB，深色为#1C1C1E/#2C2C2E/#3A3A3C。每个组合分别计算，不将气泡的on-accent与本表混用。玻璃层若背后内容导致最差组合不满足门槛，给文字区加足够实底的衬层或提高材质不透明度，不能通过降低文字opacity补救。D 阶段已验证全部透明度档位下的实际渲染（第 10.3 节）；hover/focus/错误/占位状态在 M1b 的组件里继续验证，静态计算不是完整无障碍验收。[WCAG文字对比度依据](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

2026-10-01按sRGB相对亮度公式复算：上述12个文字/背景组合最低约4.880:1，16个气泡组合最低约5.567:1。这里只验证列明的不透明基础色，实际玻璃/交互状态仍待AT-21。

### 4.2 圆角（外层圆角 = 内层圆角 + 间距，保证同心）

| 令牌 | 值 | 用途 |
|---|---|---|
| `--radius-window` | 16px | 大面板、弹层 |
| `--radius-card` | 14px | 卡片、图片附件 |
| `--radius-control` | 10px | 按钮、输入框 |
| `--radius-bubble` | 18px | 气泡。同组内相邻的一侧改为 6px；每组最后一个气泡带尾巴 |

### 4.3 字体

D4 确认（2026-10-02，D-113）：**拉丁字母和数字用 Inter，中文用系统字体，Apple 设备上仍然先用 SF。**

- **正文字体栈**：`-apple-system, BlinkMacSystemFont, "Inter", system-ui, "PingFang SC", "Segoe UI Variable Text", "Segoe UI", "Microsoft YaHei UI", "Noto Sans SC", sans-serif`
- **等宽字体栈**：`ui-monospace, "SF Mono", "Cascadia Code", Menlo, Consolas, monospace`
- **Inter 自托管**：OFL 1.1 许可证，取 `@fontsource-variable/inter` 的拉丁子集（variable，约 48 KB），`font-display: swap`，随产物附带许可证文本。CSP 的 `font-src 'self'` 已够用（07 SEC-06）。M1b 已完成：woff2 在 `apps/web/src/assets/fonts/`（48 KB，随构建带哈希），`index.html` 里预加载，许可证文本在 `public/licenses/Inter-OFL.txt`。
- **解析顺序**：Apple 设备上 `-apple-system` 排在最前，所以用 SF，Inter 不会被用到；Windows 和 Linux 上拉丁字母和数字用 Inter，Inter 加载前先用 `system-ui`；中文始终用系统字体（PingFang SC、Microsoft YaHei UI、Noto Sans SC）。
- 除 Inter 外**不下载任何字体文件**，也不打包 SF Pro / SF Mono（第 1 节的红线）。
- 比较数据见第 10.4 节：Inter 的宽度是系统字体栈的约 99%，换字体几乎不改变布局。

### 4.5 动效（Motion 13 的弹簧动画）

| 预设 | 参数 | 用途 |
|---|---|---|
| `snappy` | stiffness 500, damping 38 | 菜单、按钮反馈 |
| `smooth` | stiffness 300, damping 30 | 面板展开、切换会话 |
| `bouncy` | stiffness 400, damping 22 | 新消息插入、发送 |
| 淡入淡出 | 150–250 ms | 提示、遮罩 |

原型把三个弹簧的精确解导出成 CSS `linear()`，时长约 snappy 392 ms、smooth 506 ms、bouncy 631 ms（算法在 `tokens.mjs`）；M1b 用 Motion 14 驱动，参数不变（用到的 `layoutId` 和 `MotionConfig reducedMotion` 在 14 上正常，D-115）；系统的「减少动态效果」和设置里的开关都会让它退化为淡入淡出。

- **切换路由和会话**：优先用 View Transitions API 做过渡，浏览器不支持时直接切换。
- **元素入场**：用 `@starting-style` 实现。
- **减少动态效果**（`prefers-reduced-motion`，或在设置里开启）：所有动画都改成 ≤ 150ms 的纯透明度变化。

## 5. 聊天界面细节

- **气泡**
  - 自己的消息靠右，bubble-out 底配 on-accent 文字；别人的消息靠左，灰底配 label。
  - 群聊里，同一组消息的第一条上方显示发送者名字，头像放在最后一条的左下角，和「信息」App 一样。
- **时间**：鼠标悬停在气泡上时，在侧边显示精确时间。它不占行内空间（否则会把气泡挤窄），宽度不足 768px 时不显示（触屏没有悬停）。
- **附件**
  - 图片不套气泡，直接显示为 14px 圆角的图。多张图片时，2–4 张以网格排列。
  - 视频上叠一个播放按钮，文件显示为卡片（图标、文件名、大小、下载按钮）。
  - 图片加载前先显示 thumbhash 模糊占位图。
- **回复**：气泡上方显示引用条，写着对方名字和原文摘要。点击后跳到原消息，原消息高亮 1 秒。
- **@提及**：提及显示为高亮胶囊。@我的消息整条带淡淡的强调色背景。
- **系统消息、撤回、删除**：居中的小号灰字。
- **机器人徽标**：Agent 的名字旁边有醒目的"机器人"标签，防止有人用"助手"之类的显示名冒充；显示名本身也不能使用保留名。
- **加入前的历史**：
  - 新成员的时间线顶部显示"你于某时加入，之前的消息不可见"；
  - 引用了加入前消息的回复，引用条显示"原消息不可见"。
  - 共享助手显示“仅总结所有当前成员都能看到的讨论”；新成员加入后说明范围变化，并提供个人面板入口。
- **正在输入**：一个带三个跳动圆点的灰色气泡。
- **分隔条**："以下为新消息"用强调色细线加文字；日期分隔用居中胶囊显示。
- **右键菜单**：回复、复制、编辑、撤回、删除（仅自己）、举报、交给助手（把这条消息带进助手面板）。
- **悬停工具条**：鼠标悬停在气泡上时浮出，含回复和更多（v1.1 加表情回应）。
- **代码块**：用 Shiki 高亮，浅色和深色各一套主题，右上角有复制按钮。
- **发送状态**：发送中气泡去饱和，不降低文字不透明度（整个气泡降到 0.6–0.72 时，白字对蓝色气泡只有 2.66–3.32:1）；失败时气泡旁出现红色感叹号，点击可以重试或删除。
- **删除状态**（M7）：异地确认未完成时显示“删除待完成，内容仍可能可见”，可查看进度；完成后才显示撤回/删除占位。错误给明确重试入口，不把202当成功，也不允许重复点击扩大目标。
- **回到最新**：离开底部时，右下角浮出圆形按钮，并显示期间新到的消息数。

## 6. Agent 相关界面

- **Agent 的消息**：头像是 ✦ 图标。流式输出时，气泡边缘有流光渐变描边，风格参考 Apple Intelligence；输出完成后描边淡出。
- **流式文本**：用 Streamdown 渲染，未写完的 Markdown 也不会乱掉；末尾带闪烁的光标。
- **工具调用卡片**
  - 默认折叠成一行："正在搜索消息…" → "✓ 找到 12 条相关消息"，可以展开查看参数和结果摘要。
- **审批卡片**
  - 一张玻璃卡片，写明要做什么、做在哪里（比如"发送到 #项目组"），并完整预览将要发送的内容。
  - 三个按钮：批准（强调色）、修改、拒绝；卡片上显示剩余有效时间。
  - 运行暂停等待审批时，Agent 当前的回复先收尾：流光描边停止，末尾显示"等待 @某人 批准"。批准后，接下来的输出显示为一条新回复。
  - 通知中心和推送会同步提醒（M6）。
- **重新生成**（D-036）：
  - 悬停工具条上的“重新生成”会**替换**原回复，消息视图不保留旧版本；旧 run 副本按隐私保留期处理。
  - 只对发起人显示：
    - Agent 会话和面板里，只出现在最近一条回复上；
    - 群里 24 小时内可用；
    - 执行过任何业务效果（含提醒/记忆）、有待审批或仍在运行的回复不显示按钮。
- **助手面板（Inspector 的"助手"页）**
  - 顶部是快捷操作：总结未读、总结这段讨论、找消息、起草回复、翻译选中内容。
  - 快捷操作上方有读取范围开关："只看当前会话"（默认）/"我的全部会话"。切换到后者时，给出一句简短说明（D-051）。
  - 下面是与 Agent 的对话流，和当前会话绑定，只有自己可见。每次切换范围开启新上下文段，并显示“范围已切换，新对话不会沿用上一范围的上下文”；旧段不自动送给模型。
  - 起草的结果带"插入输入框"按钮，**不会**直接发出。
- **⌘K 命令面板**：居中的玻璃弹层。可以在这里跳转会话、执行命令（如 `/总结`、`/翻译`、`/提醒我 …`），或直接向 Agent 提问。
- **key来源切换**：显示当前来源；切换创建空白上下文段，说明旧私有上下文不会自动带入。BYOK失败时按钮为“使用站点额度发起新请求”，不自动填回原文/图片；隐私说明可查看，鼓励文案仍只讲好处。
- **任务与时区**：提醒/定时消息卡完整显示日期、时区、UTC偏移、来源设备和取消入口。设备安全撤销前显示受影响任务；普通退出说明后台任务继续。重复/不存在的DST时刻要求明确选择，固定时区跨设备保持一致。
- **记忆**：Agent 记住一件事时，会出现"已记住：…"的小标签，可以撤销。所有记忆在设置里统一管理。
- **用量**：助手面板底部用一行小字显示今日用量，比如"今日已用 12%"；使用自带 key 时显示"正在使用你的 API key"。
- **自带 key**（M5，设置 → 助手）：
  - 界面：一个输入框（保存后只显示末 4 位）、"验证并保存"和"删除"两个按钮；key 失效时显示原因。
  - 文案只讲好处：不占每日额度，全站额度用完时也能照常使用（D-034）。
  - 额度用完的提示里，可以附上"使用自己的 API key"的入口。

## 7. 可访问性与键盘

- **对比度与缩放**：D 和 M1b 测 8 色 × 深浅 × 4 透明度的关键文字/控件，最差玻璃背景也满足正文 4.5:1（D 阶段的脚本和像素级审计结果见第 10.3 节）；200% 字号无裁剪、400% 缩放在 320 CSS px 可完成登录、导航、收发与审批。
- **控件边界**：输入框、开关轨道、复选框、滑块的描边用 `--control-border`（对所有表面不低于 3:1）；分段控件选中的滑块带 1px 描边（白滑块对灰轨道只有 1.1:1）。
- **焦点**：`:focus-visible` 时显示 2px 强调色焦点环，外扩 2px。可点击区域不小于 28×28px。
- **读屏**
  - 列表用"漫游 tabindex"方式做键盘导航（方向键在项目间移动）。
  - 新消息通过 `aria-live="polite"` 播报。只播报当前打开的会话；短时间内的多条消息合并成一次播报，避免在热闹的频道里刷屏。
  - 虚拟列表为每一项补上 `aria-setsize` 和 `aria-posinset`。
  - 所有图标按钮都要有 `aria-label`。
  - 虚拟列表不能移除当前键盘焦点；提供按页载入的读屏模式和“载入更早消息”按钮，NVDA/VoiceOver 实测阅读顺序。工具菜单同时提供键盘可见入口，弹层关闭后焦点返回触发点；Agent 只播报阶段/完成，不逐 token 播报。
- **快捷键**（Windows 上 ⌘ 对应 Ctrl）：
  - 不使用浏览器保留的组合键，比如 ⌘N、⌘T、⌘W：网页在 Chrome、Edge 的标签页里拦截不到它们（D-052）。
  - 每个快捷键都要在 Chrome、Edge、Safari、Firefox 里实测（V-16）。
  - 所有功能都能在 ⌘K 里找到，快捷键只是捷径。

| 快捷键 | 动作 |
|---|---|
| ⌘K | 命令面板，也用来新建会话、搜索消息、打开设置 |
| ⌘J | 打开或关闭助手面板 |
| ⌥↑ / ⌥↓ | 切换到上一个 / 下一个会话 |
| ⌥⇧↑ / ⌥⇧↓ | 切换到上一个 / 下一个未读会话 |
| ↑（输入框为空时） | 编辑自己的上一条消息 |
| Enter / ⇧Enter | 发送 / 换行 |
| Esc | 关闭弹层，取消编辑或回复 |
| ⌘/ | 快捷键帮助 |
| ⌘, | 设置（浏览器不拦截时有效；否则在 ⌘K 里输入"设置"） |

新建会话用 ⌘K 或侧边栏的"+"按钮。安装为 PWA 后，如果浏览器允许，再给新建会话绑定 ⌘N（M6 实测）。

## 10. D 阶段成果（2026-10-02，D4 已确认）

> 本节记录 D 阶段做出了什么、实测结果，以及对第 2 到 7 节的修订。用户已在 D4（2026-10-02）确认，确认的值已并入那几节，本节留作依据。没有跑过的检查在 10.7 里列明。

### 10.1 原型与检查

- **位置与构建**：`design/prototype/`，说明见 [design/README.md](../design/README.md)。`bun run design:build` 构建，加 `-- --minify` 得到发布版。产物在 `dist/`（git 忽略）：`artifact.html` 是 Artifact 要求的片段形式，`index.html` 用于本地查看。**不依赖网络**：样式、脚本、图标和 Inter 的拉丁子集全部内嵌。
- **范围**：D3 清单里的界面都有，浅色和深色各一套：登录、带邀请码的注册、验证邮箱、邮件链接确认、找回与重置密码；频道（图片、回复、@提及）、私信、群组加右侧成员面板、Agent 会话（流式输出、工具卡）、助手面板（总结未读）、审批卡与等待批准、⌘K、设置（外观、通知、账号与设备、邀请、助手）、新成员视角、通知中心、空状态、应用图标草案。另有：提醒/定时消息与夏令时确认、自带 key 失败、消息状态陈列、断网、快捷键帮助、宽度分层（1440 到 320）。顶部的审阅控制条切换场景、主题、8 个强调色、4 档透明度、窗口宽度、字体、字号档位。
- **技术**：令牌数据 `tools/tokens.mjs` 是单一数据源，生成 CSS、驱动对比度检查，也是"设计说明"页的数据。颜色用 `light-dark()`，弹簧动画导出成 CSS `linear()`，布局断点用容器查询。界面用 `createElement` 构建，没有 `innerHTML`。

| 命令 | 检查什么 |
|---|---|
| `bun run design:contrast` | 令牌静态对比度，3018 组（含 8 色 × 深浅 × 4 档透明度的侧栏玻璃） |
| `design/prototype/tools/browser-checks/run.sh keyboard` | 键盘主流程、焦点陷阱与返回、输入法组字规则、鼠标点击模态内容（46 项） |

### 10.3 对比度结果

- **静态**（`bun run design:contrast`，2026-10-02）：3018 组，0 组低于阈值。最紧的几项：深色输入框底色上的占位文字 4.56:1，侧栏选中行（深色黄、着色档）上的次要文字 4.54:1，浅色气泡上的强调色文字 4.69:1。
- **像素级**（`run.sh audit full`）：8 个强调色 × 深浅 × 4 档透明度，各渲染一屏聊天界面（64 屏）；再在最不利的 12 个组合（蓝、黄、石墨 × 清透、着色 × 深浅）上渲染菜单、命令面板、Inspector 浮层、设置面板（48 屏）。取每处文字外围 3px 一圈像素的中位数当背景，把文字色（含透明度）合成上去。**结果见 PROGRESS 的记录**（数字以那里为准，随最终构建更新）。
- **做法上的限制**：取样环有时会碰到相邻的元素（未读徽标的环越出药丸、输入框的环碰到分隔线），所以用中位背景判定，第 5 百分位只作参考；这类"软失败"都是中位对比度 5.5 以上的元素。纯黑、纯白、高对比图案背后的承载文字玻璃，在"玻璃对照板"页上可以目测；真实照片、悬停和焦点状态的像素级检查没做。
- **实测抓到的缺陷**（都已修）：玻璃层 19 层（每条消息的悬停工具条都带模糊）、模态面板被自己的遮罩压暗并且点不到、抽屉被遮罩盖住、时间线重绘丢键盘焦点、关闭弹层后焦点没回到原控件（侧栏重绘后节点已被替换）、主题监听死循环、窄屏下"精确时间"把气泡挤成 127px。

### 10.4 字体（D1）

在 Windows 11（Edge 154）上，系统字体栈解析为 Segoe UI（Variable）加 Microsoft YaHei UI；这台机器没有 SF、PingFang、Menlo、Inter。Inter 用拉丁子集（variable，48 KB，OFL）内嵌。

- **宽度**：同一段文字，Inter 的宽度是系统栈的 98.5%（拉丁）、99.0%（数字）、99.2%（人名）、98.9%（中英混排）。切换字体几乎不会让布局跳动。
- **形状**：Inter 的 x 高度略高（15px 下约 9px 对 8px，取整后的值），数字 `1`、`y` 的形状更接近 SF。中文界面里差别主要出现在数字、时间、英文人名和徽标上。
- **成本**：Inter 多 48 KB，缓存后只下载一次；`font-display: swap`，不阻塞首屏。Apple 设备上栈里 `-apple-system` 排在前面，仍然用 SF。
- **结论（D4，2026-10-02）**：用 Inter。拉丁字母和数字用 Inter，中文用系统字体，Apple 设备上仍然先用 SF（D-113）。理由：产品要的"Apple 味"主要由数字、时间和英文字母体现，这些恰好是 Inter 最接近 SF 的地方，换字体又不改变布局。最终字体栈写在第 4.3 节。

### 10.5 应用图标草案

三个原创方向，没有用 Apple 的图标或 SF Symbols：A 白色气泡加四角星（蓝紫渐变底）；B 两个叠放的玻璃气泡（夜蓝底）；C 气泡形状的渐变环加四角星（浅色底）。设计说明页可以对比、看 maskable 安全区。

**D4 选 A**（用户说"先随便选一个你觉得最好看的就行"，所以是暂定，M6 导出前还可以调整）。理由：只有 A 在 16 到 32px 的小尺寸和浅色、深色背景上都认得出来；B 在深色背景上边缘几乎消失、小尺寸糊成一团，C 在浅色背景上和白色融在一起。A 的蓝色和默认强调色一致，四角星和界面里助手的 ✦ 是同一个符号。按几何估算，A 的主体在 maskable 安全区（直径 80% 的圆）以内，没有导出验证。

导出 192、512、maskable 和 favicon 在 M6 的 PWA 里做；maskable 要用满版的方底（不带圆角）。A 的构图（彩色底加白色气泡）和 Apple「信息」图标有相似之处，颜色、气泡形状和四角星都是自己的，我认为区别足够，但没有做过商标或相似度检索，导出前请再看一眼。

### 10.7 没有验证的

D4 的确认不改变下面这些：它们仍然没有验证，留给 M1b（Playwright 的 Chromium、WebKit，Firefox 冒烟，V-16 快捷键实测）和真机验收。

- **macOS Safari、Firefox 的渲染**，以及 `corner-shape`、`light-dark()`、容器查询、`@property` 在它们里的表现；规格要求的 Windows Chrome 只看了 Edge（同一内核）。
- **读屏**（NVDA、VoiceOver）的阅读顺序和播报；只验证了 DOM 角色、标签和焦点行为。
- **快捷键在各浏览器里的冲突（V-16）**：用的是 CDP 发的键盘事件，浏览器自己的快捷键（如 Ctrl+K 聚焦地址栏）不会触发，所以这项没有被覆盖。
- 系统高对比度（forced colors）模式；Windows 的"透明效果"开关；手机和触屏交互（v1.1）。
- 真实照片垫在玻璃后面时的像素级对比度。
