# 当前项目全面审查 · 2026-10-16

## 1. 结论与审查基线

当前项目的主要能力已形成完整实现，工程基础较扎实；下一阶段更应投入到复杂使用场景、错误恢复、管理体验和生产验收。现有测试与 CI 通过，但本轮仍找到 **10 项具体缺陷：8 项在真实前端组件的隔离浏览器场景复现，1 项在真实后端函数的受控故障场景复现，1 项由源码路径确认、等待真实数据库验证**。另有管理审计、导航、文档与容量方面的改进项。

本轮没有取得新的 P0/P1 权限越界或内容泄露证据。这不构成全面安全认证，也不表示完整 M7 或正式开放已经通过。P2 表示应排期解决的功能/可靠性缺陷；P3 表示影响相对有限的一致性问题。自动工具的 `critical` 标签与本报告的产品风险级别不是同一套分类。

## 2. 具体缺陷

### R01 · P2 · 历史记录会把仍待执行的任务挤出管理界面

**位置**：[assistant-section.tsx](../apps/web/src/features/settings/assistant-section.tsx) L278–318；[agent.ts](../packages/contracts/src/agent.ts) L268–280；[tasks.ts](../apps/server/src/domain/tasks.ts) L344–389。

设置页分别请求提醒和定时消息的第一页，忽略 `nextCursor`，也不传状态过滤条件。接口默认每页 50 条，按创建时间倒序排列，包含已完成/已取消历史。

**复现**：第一页返回 50 条较新创建的已发送任务及非空游标，第二页有一条较早创建、仍待执行的定时消息。真实 `AssistantSection` 显示 50 行，只有一次 `/api/scheduled-messages` 请求，没有游标请求或继续加载入口，待执行项无法在设置页查看和取消。任务并未因此停止执行。

**建议**：待执行与历史分区或按状态筛选，两个来源分别实现游标分页，再明确合并排序；不能只把默认 50 改成更大的数字。**验收**：51+ 条、已完成历史多于待执行、两种任务混合及取消后翻页，所有待执行项均可到达且取消反馈正确。

证据：`browser-extra-attempt3.json` 的 `tasks-ignore-next-cursor`，`tasks-tail.png`。

### R02 · P2 · 最后一个管理员可以经账号注销绕过管理席位保护

**位置**：[account-deletion.ts](../apps/server/src/domain/account-deletion.ts) L101–126、L351–370；对照 [site-admin.ts](../apps/server/src/domain/site-admin.ts) L257–302。

管理端降级/封禁管理员时会串行化管理员角色变更，并要求存在另一位有效管理员。账号注销入口只验证当前身份和密码，随后准备不可逆删除；执行阶段会把角色设为 `user` 并写入 `deletedAt`。该路径没有同等的最后管理员检查，也没有获取管理员角色锁。本轮搜索未发现数据库迁移中的等价兜底约束。

**影响**：若唯一有效管理员注销账号，站点会失去可用管理账号，邀请、举报和政策管理只能经运维入口恢复。两位管理员并发注销、或注销与降级交错也需要统一考虑。

**证据级别**：源码路径确认，未执行真实数据库注销，也未验证生产是否只有一位管理员。不能把它说成已发生的生产事故。

**建议**：先设计接任/新增管理员流程，在删除意图进入不可逆阶段前检查并串行化所有会减少有效管理员的操作。检查应同时考虑已经准备注销的账号；仅查询另一行 `role=admin` 不足以处理并发注销。**验收**：唯一管理员、两位并发注销、注销与降级/封禁交错，以及接任成功后注销；使用真实 Postgres 和删除 journal 隔离环境。

### R03 · P2 · 举报落库与通知分离，故障后重试不会补发

**位置**：[reports.ts](../apps/server/src/domain/reports.ts) L60–98；[notifications.ts](../apps/server/src/domain/notifications.ts) L94–116。

举报和幂等回执先在事务中完成，随后只有 `result.new` 才调用 `notifyAdmins`。此时若进程退出或通知事务失败，举报已经存在，但通知可能没有创建。重试同一幂等键得到 `new:false`，不会补发；换幂等键也会因已有举报而得到 `new:false`。多位管理员逐个写通知时，还可能只有前面几位收到。

**复现**：调用真实 `submitReport`，用内存事务/授权端口和失败通知端口注入“提交后通知失败”。第一次抛错，举报已存在；相同请求重试返回举报编号，但通知尝试次数仍是 1。此证据验证控制流，不代替真实 SQL 崩溃恢复测试。举报本身仍可在管理列表中找到。

**建议**：举报事务内写入持久通知工作项，后台按举报与管理员去重重试。避免为了原子通知在原事务里随意扩大跨用户锁范围。**验收**：提交后终止进程、首位/中间管理员通知失败、重启补偿与重复执行；每位目标管理员最终收到一条通知。

证据：`report-notification-probe.ts`、`report-notification-probe-attempt2.log`。

### R04 · P2 · 保存记忆的迟到成功响应会清空新草稿

**位置**：[memories-group.tsx](../apps/web/src/features/settings/memories-group.tsx) L32–46、L77–79。

提交后输入框仍可编辑，但成功回调无条件执行 `setDraft('')` 和 `setAllowSite(false)`。账号身份保护不能区分同一个账号在等待期间输入的新内容。

**复现**：提交第一条记忆，阻塞响应，输入第二条尚未保存的记忆，再放行第一条的成功响应。第二条输入从 `second unsaved memory` 变为空字符串。

**建议**：把本次提交的文本、分享选择及草稿修订号作为请求快照；只有当前草稿仍对应此快照才清理。也可明确禁止等待期间继续编辑，但交互要说清楚。**验收**：迟到成功、迟到失败、等待期间修改分享选项、重复提交及账号切换；不得损失后输入的内容。

证据：`browser-probes-attempt3.json` 的 `memory-draft-lost`，`memory-draft-after.png`。

### R05 · P2 · 消息搜索静默截断为前 20 条

**位置**：[app-frame.tsx](../apps/web/src/features/shell/app-frame.tsx) L297–328。

命令面板请求 `limit=20`，随后只映射 `result.messages`，丢弃服务端返回的分页游标。界面既没有继续加载，也没有“仅显示部分结果”的提示。结果副标题只有时间，没有会话或发送者，跨会话同文结果难以区分。

**复现**：在真实 `AppFrame` 打开命令面板搜索，合成接口返回 20 条及非空 `nextCursor`。页面只有 20 个选项，没有后续请求或更多结果入口。较旧的匹配消息无法经这次搜索继续找到。

**建议**：保留命令面板的快捷搜索，并提供完整搜索结果页/继续搜索入口，显式显示范围、会话和发送者。当前请求未传会话限制；这是产品范围表达问题，本轮没有据此认定越权读取。**验收**：21+ 条、跨会话同文、空结果、失效游标、撤回或权限变化后的结果，以及点击后的准确定位。

证据：`browser-extra-attempt3.json` 的 `search-truncated-in-real-shell`，`search-truncated.png`。

### R06 · P2 · 命令面板键盘选择不会把当前项滚入视野

**位置**：[command-palette.tsx](../apps/web/src/features/command-palette/command-palette.tsx) L136–164、L192–222。

方向键/Home/End 只更新 active 状态。焦点留在输入框，通过 `aria-activedescendant` 指向选项；浏览器不会因此自动滚动列表，代码也没有对应滚动处理。

**复现**：真实组件显示 35 项命令，按 End 后第 35 项已成为当前项，但滚动位置仍是 0，当前项在可视列表之外；此时 Enter 会执行看不见的选项。

**建议**：在当前选项或结果集合变化后，将选项滚入最近可视区域；保持输入框焦点和读屏语义。**验收**：长列表 ArrowUp/Down、Home/End、首尾循环及异步搜索结果到达，当前选项始终可见。只用 jsdom 检查 `aria-selected` 无法验证这一点。

证据：`browser-probes-attempt3.json` 的 `palette-active-option-offscreen`，`palette-offscreen.png`。

### R07 · P2 · 有歧义时间的审批先点“修改”会陷入无法批准的状态

**位置**：[approval-card.tsx](../apps/web/src/features/agent/approval-card.tsx) L305–339。

遇到夏令时回拨的两个候选时间时，必须先选一个时间才能批准。但“修改”会隐藏整个 Preview，连同时间选项一起消失，保存并批准仍因未选择时间而禁用；界面没有取消编辑/返回预览按钮。

**复现**：以 `America/New_York` 的 `2026-11-01 01:30` 两个候选时刻构造审批，先点“修改”。radio 从 2 个变为 0，批准按钮仍禁用。用户只能拒绝或离开后重建组件才能回到选择时间的流程。

**建议**：编辑正文时保留目标会话、时区和时间选择；增加取消编辑。**验收**：先编辑后选时间、先选时间后编辑、取消编辑、批准失败后的重试，最终发送目标及时间与可见预览一致。

证据：`browser-probes-attempt3.json` 的 `ambiguous-time-edit-dead-end`，`approval-edit-dead-end.png`。

### R08 · P2 · 768–1023px 的侧栏折叠按钮丢失可访问名称

**位置**：[sidebar-list.tsx](../apps/web/src/features/conversations/sidebar-list.tsx) L114–124；[shell.css](../apps/web/src/styles/shell.css) L492–541。

中等宽度的 rail 模式隐藏折叠按钮里的文字和图标，但保留按钮本身及其焦点入口，也没有 `aria-label`。按钮高度缩到 8px，视觉上也很难理解或操作。

**复现**：真实 `AppFrame`、一个已存在群组、768px 视口；浅/深主题均触发 axe `button-name`，对象为 `.s-section__toggle`。320px 和 1440px 的同一外壳场景没有这项问题，说明单独验证手机最窄和桌面宽屏会遗漏中间断点。

**建议**：明确 rail 模式是否支持分组折叠。如果保留，提供稳定的可访问名称及可见可操作的控制；若移除，不能留下空白可聚焦元素，同时必须能展开此前已折叠的分组。**验收**：767/768/1023/1024 边界、桌面折叠后缩窗、键盘 Tab/Space 和读屏检查。

证据：`design-probes-attempt2.json`，`shell-768-light.png`、`shell-768-dark.png`。axe 的 `critical` 是可访问性影响标签，并非安全 P0。

### R09 · P2 · AI 用量请求失败后仍显示“正在加载”

**位置**：[usage.tsx](../apps/web/src/features/agent/usage.tsx) L12–17、L48–50。

组件只读取 query 的 `data`，未区分首次加载和失败。无数据时所有状态都渲染“正在加载”，用户无法识别权限/服务故障。15 秒轮询仍存在，故这里不是“完全不会重试”；持续失败时会持续给出错误的加载提示。

**复现**：让真实请求收到合成 403，查询状态已是 `error`、`fetchStatus=idle`、错误码 `FORBIDDEN`，页面仍显示“AI 用量 / 正在加载…”。

**建议**：区分未启用、加载、失败和已成功但刷新失败；有历史数据时显示更新时间和刷新失败提示，无历史数据时给出明确错误与重试。**验收**：首次 403/503、离线、恢复、已有数据刷新失败，不把未知额度显示成零或无限。

证据：`browser-extra-attempt3.json` 的 `usage-error-disguised-as-loading`，`usage-error-loading.png`。

### R10 · P3 · 管理页切换分类后搜索框与实际条件不一致

**位置**：[admin-page.tsx](../apps/web/src/features/admin/admin-page.tsx) L307–332。

分类切换时 `setSearch('')` 清除了查询条件，但成员与会话页复用的 TextField 是非受控输入，仍保留原先的文字。

**复现**：成员页搜索 Alice，再切到“频道与群组”。输入框仍显示 Alice，实际请求却是没有 query 参数的 `/api/admin/conversations`。用户可能以为结果经过筛选。

**建议**：区分输入草稿与已应用过滤条件，并让切换分类按明确规则同时重置/保留两者；分页状态也随条件变化重置。**验收**：成员↔会话切换、提交查询、翻页和返回，显示的条件与实际请求一致。

证据：`browser-probes-attempt3.json` 的 `admin-search-field-disagrees-with-request`，`admin-stale-search.png`。

## 3. 产品与设计上的不足

### D01 · 管理审计记录缺少可用于追溯的对象信息

[site-admin.ts](../apps/server/src/domain/site-admin.ts) L221–236 从已有审计记录只投影动作、操作者名称、对象类型和时间；[admin.ts](../packages/contracts/src/admin.ts) L138–148 的响应也没有对象标识/安全摘要。管理页 L570–585 实际只展示动作、操作者和时间。

因此两次“封禁用户”或“查看举报上下文”在页面上可能无法区分操作了谁/哪份举报。底层审计仍保留 `targetId` 和 metadata，所以这是管理产品能力缺口，不能说日志没有记录。

建议返回经过白名单处理且受权限控制的目标摘要、关联入口及必要的变更概要，支持动作/时间/操作者筛选。不要为了可读性暴露消息正文、邮箱、密钥，或直接把全部 metadata 输出。建议按 P2 排期，验收时确认管理员能从一次投诉追到相应操作与目标。

### D02 · 首次使用与窄窗口导航偏重“已经会用的人”

实际外壳在 320px 和 1440px 的浅/深主题下没有横向溢出，本轮自动可访问性检查也通过；现有色彩/字体/玻璃样式无需全盘重做。但欢迎页的主要内容是快捷键清单，缺少醒目的“开始私聊 / 浏览频道 / 与助手对话”等下一步操作。

768–1023px 下“新建”入口、会话文字和完整侧栏都被收起，打开侧栏的工具栏按钮只在 <768px 显示。部分操作仍可从搜索/命令面板到达，因此不能说功能完全不可用；但用户需要自行发现替代路径，断点切换也改变了操作习惯。

建议保留 2–3 个高频直接入口，在 rail 模式提供明确的展开或新建控制。快捷键放到次级帮助；搜索结果增加来源和范围；助手设置中的用量、密钥、任务、记忆分别提供明确的状态与失败恢复。验收应包含首次使用者完成真实任务，而不只看静态截图。

### D03 · 当前状态与历史记录分散，容易误判完成度

[README](../README.md) L9–16 仍把主要功能标作“计划中”，并把现已实现的审批、提醒、BYOK、记忆归入后续 M5。审查前的 PROGRESS 顶部和 [35](35-closed-deployment-2026-10-16.md) 仍描述旧生产版本及等待 CI，而当前 SHA 的工作流已全部成功。

更晚的本地 `next-state.json` 元数据记录当前版本为 `a212e9d…`、封闭部署完成、本地/远端/部署 SHA 一致，且 `formalPublicRelease=false`、`fullM7Accepted=false`。这是较新的历史回执，本轮没有独立连接服务器验证其现时状态。

建议保留全部历史记录，同时建立一页简明的当前状态索引：源码 SHA、最后一次部署核验时间、确切 CI、已开放范围、仍未验收的门槛。公开摘要只从允许字段生成，不把私有服务器地址或凭据写入文档。本轮只追加审查记录，未把旧部署记录改写成新验证事实。

## 4. 架构与可靠性风险

| 主题 | 当前观察 | 实际含义与下一步 |
| --- | --- | --- |
| 保留清理的锁范围 | `retention.ts` L62–66 先选择并锁住全部用户；随后处理所有过期运行和对象。运行每 500 条循环仍在同一事务内 | 与 `sessions.ts` L110–138 的业务写入用户锁相遇，会放大锁等待。未实测尾延迟超标；应在目标规模下重叠聊天、清理和备份，测锁等待、事务时长、队列年龄、p95/p99 |
| 清理与删除保障 | journal 接受、目标冻结和本地应用组成安全边界 | 不能为缩短事务随意拆批，否则可能破坏恢复时删除不复活的保证。任何缩小锁范围/分段方案均需重新证明冻结及重放不变量 |
| 事务后副作用 | 举报通知存在 R03；预算阈值通知则在通知成功后才写 announced 标记 | 不应把所有“事务后执行”一概判错。应逐项确认意图是否持久化、是否有扫描补偿，以及重复调用能否安全去重 |
| 跨入口业务不变量 | 最后管理员保护只在管理变更入口体现，账号注销另走一套流程 | 将共享不变量集中到 domain 层，在角色变更、注销、恢复权限确认等入口保持统一；测试要覆盖入口之间的交错 |
| 前端状态实现 | 主聊天已具备请求身份、会话世代与草稿收尾保护；设置/管理子功能仍出现 R04/R09/R10 | 需要复用已验证的状态处理模式，而不只是增加样式组件；区分请求归属、编辑修订、查询状态与实体版本 |
| 管理页维护成本 | `admin-page.tsx` 1151 行，含列表、编辑表单、恢复权限等多种职责 | 文件长度本身不是缺陷；但路由状态、查询条件、mutation 错误和审计展示分散，改一个流程难以独立验证。优先按业务页面拆分查询/表单，保留统一权限入口 |

这些是源码可见的风险或维护成本，未通过目标生产负载验证的性能项均不标作已发生故障。

## 5. 性能、可访问性与测试体系

构建产生 106 个预缓存资源，总量约 2713.72 KiB。存在约 1.03 MB 的 C++ 语法 chunk 提示，但代码已按需加载语法，并通过 `precacheIgnores` 把这些语法包排除在预缓存之外；不能把这条提示直接写成“首屏必下 1 MB”。建议测量冷启动网络、下载压缩后大小、脚本解析和低性能设备交互，再决定拆分策略。

现有校验覆盖类型、后端/工具逻辑、前端、对比度、国际化、真实基础设施与浏览器 CI，是有价值的基础。本轮发现的遗漏主要来自四类场景：

1. **规模边界**：首屏能显示，但第二页是否可达；历史记录是否遮住仍有效的工作。
2. **时间交错**：旧请求成功时用户已经开始新输入；进入编辑后另一项必选输入是否仍可达。
3. **故障窗口**：数据库提交后、副作用之前失败；首次请求最终失败时 UI 是否仍声称加载。
4. **布局断点与真实几何**：ARIA 当前项正确但在屏幕外；最窄和最宽都通过，中间断点却丢失名称。

建议把本报告的最小复现转成正式回归，并在正常实现修复后验证“用户最终能完成任务”。其中分页/草稿/审批/几何要用真实浏览器，管理员与通知要用真实数据库及受控进程故障；不要只复制当前实现逻辑写断言。

自动 axe 检查仅覆盖本轮构造的外壳场景。读屏阅读顺序、真实 Passkey、平台快捷键、安装窗口、真实推送/国内网络和本人验收仍需各自证据。历史已确认的项目不在本轮被重新宣称通过或否定。

## 6. 发布与运行状态的判断

目前可支持的是：当前源码本地检查通过、当前 SHA 远端 CI 全绿，以及本地历史回执记载的封闭部署完成。完整 M7 和公开运行准备仍不能仅凭这些结论关闭。

根据最新本地回执的 `nextActions`、[35](35-closed-deployment-2026-10-16.md) 与 [测试规格](08-testing.md)，后续至少要分别核验：

- **目标容量和混合负载**：1000 用户、百万消息、10GB 对象测试集、500 WS、热点与慢连接、模型/媒体/备份/清理重叠及故障矩阵。小样本聊天 smoke 不能代替它。
- **运营可见性**：外部告警真正到达、备份与保留策略跨周期执行、积压/失败能被发现。旧部署文档记录外部告警禁用、保留清理未安装，本轮未复验现场；不能推断它们现在已经启用。
- **实际业务链路**：线上启用的模型/向量配置、真实邮件/附件/AI 操作与本人使用体验；测试中可用的能力不能直接算作生产已启用。
- **独立恢复**：按 D-210 在整台源主机不可访问时，仅凭异地备份、journal 和另存材料恢复干净环境，验证删除不复活、权限再确认及连续 RPO/RTO。材料解密/hash 校验不等于完成这项演练。停机维护另按原流程安排，本次审查未执行。
