# 维护原则与历史决策

`main` 为当前维护主线。此处保留仍需遵守的核心约束，完整 D-001–D-214、实验、例外与阶段授权保存在[清理前决策记录](https://github.com/liaboveall/ChatApp/blob/v2-pre-cleanup-2026-10-20/docs/12-decisions.md)。

历史决策描述其发生时的上下文。历史“未实现”“未上线”及阶段授权不作为当前状态或新的操作授权；用户最新要求优先，行为变更同步代码、规格与测试。

## 产品

- 邀请制注册，桌面优先，Apple Liquid Glass 风格（2026-11-13 起：内容铺满窗口，导航与控件作为玻璃悬浮其上，见 docs/02），中英双语、深浅主题与 PWA。
- 2026-11-13 起维护者决定生产网关对公众开放，不再按 IP 允许清单封闭；注册仍凭邀请码并验证邮箱。工具默认仍生成封闭策略，公开须显式选择。
- 新成员不可查看加入前的消息，引用、预览、附件、搜索与助手使用同一可见性规则。
- 助手“重新生成”替换原回复；共享输出限于共享来源，影响他人的操作先审批。
- 站点 AI 默认使用 SoCLaaS，缺 key 或调用失败不自动切换付费服务。个人密钥内容与站点密钥上下文隔离；实际隐私说明与管理员可见能力一致。

## 可靠性与安全

- PostgreSQL 是业务事实来源；业务、日志、任务意图同事务，队列与事件总线可重建（D-056）。
- HTTP / WS 从服务端 session 识别用户，后台使用受限 delegation，业务写入在事务内复核权限（D-079）。
- 普通 WebSocket 不带消息正文；流式、附件和搜索按当前权限逐项投影。
- 账号和成员变化后丢弃旧响应，退出取消在途请求；全局副作用、Cookie 与页面状态都需防迟到污染（D-171、D-173–D-175）。
- 媒体解码无网络、无业务凭据，独立容器执行；前端不渲染原始用户 HTML。
- 模型、邮件、推送等外部效果不保证恰好一次；未知调用保守记账，不盲目重发。
- 删除成功先有独立异地 journal；恢复重放删除并保持隔离，旧权限与凭据不得未经确认重新生效。

- 使用 Bun workspaces，锁定精确依赖版本，提交 `bun.lock`；升级通过相应原生架构、媒体和浏览器回归。
- 令牌唯一来源为 `apps/web/src/design/tokens.ts`，颜色与对比度检查使用当前 Web 工具（D-114）。
- 完整迁移链、回归测试、Storybook、开发启动和备份恢复工具继续保留。
- 本地、模拟、CI、目标服务器、容量、恢复与人工证据分开记录；没跑过不能说通过。
- 生产与测试数据、凭据及存储隔离；故障测试只操作有归属凭据的独立实例。
- 不因清理仓库删除部署回执、恢复材料、密钥或数据卷；历史源码与报告使用不可变标签查阅。

## 2026-11-13：界面重构为悬浮玻璃（分支 `feat/liquid-glass-redesign`）

维护者要求按 Apple Liquid Glass 的方向全面重做前端，并审视各项操作。本轮在新分支上完成，未合并、未部署；设计细节以 [02 设计规范](02-design-system.md) 为准，这里只记决定和验证。

- **布局**：放弃"三块浮在壁纸上的面板"。窗口本身是内容的底，会话铺满；侧栏、标题胶囊、工具胶囊、输入栏、Inspector 是浮在上面的玻璃。原来单独的"成员"图标并入标题胶囊（名称仍是"成员与详情"）。输入栏改为浮在时间线之上，时间线末尾的留白跟随输入栏的实测高度。
- **对比度的取舍不变**：承载文字的玻璃仍受不透明度下限约束（90%）。新增只放图标的 `.glass-clear`，下限由 `tools/contrast.ts` 按非文字的 3:1 反推（44% / 56%），所以真正通透的只有图标控件和壁纸上的侧栏。强调色实底在深色主题下改为白字可读的深一档，`on-accent` 两种主题都是白色。
- **不采用的做法**：不使用折射类 SVG 滤镜（只有 Chromium 支持作为 `backdrop-filter`，且成本高）；`corner-shape: squircle` 只留给频道方块（同一数值在支持的引擎里更尖，破坏同心）；下拉框不改写成自绘组件，而是在支持 `appearance: base-select` 的浏览器里绘制原生 `<select>` 的选择器，其余浏览器保留系统弹出列表。
- **操作上的补充**：emoji 分组与最近使用（按账号存在本机，已写入隐私说明）、⌘B / ⌘I / ⌘⇧X 格式快捷键、文件可拖到会话任意位置、侧栏草稿提示、消息头像的资料卡与发私信、发送者名字旁的"机器人"标签、助手流式回复的光带、纯图片与纯 emoji 消息不套气泡、确认框居中、Toast 移到顶部。
- **没有做**：表情回应、置顶消息、转发等需要新表与同步日志的功能仍在 v1.1 清单里；本轮没有改动后端、契约和数据库。
- **基线与素材**：Storybook 截图基线 148 张全部在官方 Playwright 镜像内重新生成；README 与产品导览的中英文截图和动图按新界面重拍。
- **本地验证**（WSL，未经 CI）：`bun run check` 通过（后端与脚本 703 项、前端 770 项、对比度 2400 组、文案 1036 条两种语言）；组件浏览器回归 58 项（Chromium、WebKit）；Chromium 端到端全量 176 项，之后只改了拖放的锁定判断和资料卡随滚动收起两处，并对其补跑了 33 项子集；WebKit 子集 39 项、Firefox 冒烟 33 项、性能场景 5 项；官方镜像内视觉回归 154 项对新基线通过；真实解码的媒体浏览器链 8 项通过（第一轮 WebKit 有 1 项因媒体任务以 `invalid_input` 拒绝一张图片而失败，单独重跑和其后两轮完整运行均为 8/8，未能复现）。WebKit 与 Firefox 没有跑全量，移动设备和真实读屏没有实测。

## 2026-11-13：浅色主题改为米白（同一分支）

维护者在本机试用后认为浅色主题的底色偏冷，要求试一版米白。本条只改浅色主题的取值，深色主题、布局和后端不变；取值见 [02 设计规范](02-design-system.md) 第 4.1 节。

- **取值原则**：窗口底 #FAF7F1、壁纸底 #F3EFE7、弹层 #FFFDF9、别人的气泡 #EEE9DF；文字的灰、分隔线、控件底色与描边、代码块、玻璃底色、阴影全部换成同一方向的暖色，每个值与它取代的冷灰亮度相同或更深，对比度门槛不放宽。
- **壁纸的光**：浅色主题降到 24%，下方那一块固定为暖杏色（不随强调色变），对比度脚本把它作为侧栏玻璃的又一种背景检查；登录页为 40% / 58%。
- **顺带修正**：登录页的光原先用 `light-dark()` 写百分比，是无效声明，所以重构后的登录页两种主题都没有光；现在按主题分别设值，深色登录页的画面因此也变了。
- **基线与素材**：Storybook 截图基线 148 张重新生成；README 与产品导览的中英文截图和动图重拍。
- **本地验证**（WSL，未经 CI）：`bun run check` 通过（后端与脚本 703 项、前端 770 项、对比度 2592 组、文案 1036 条）；Chromium 端到端的外壳与无障碍两个文件 32 项通过；官方镜像内视觉回归重新生成基线后再比对一遍，154 项通过。其余端到端、WebKit、Firefox、性能和媒体浏览器链没有在这次改色之后重跑。维护者试用后确认采用米白。

## 2026-11-13：强调色改为一组颜料（默认墨水蓝，新增青），气泡尾巴重画（同一分支）

维护者试用后指出默认的蓝在深浅两种主题下都刺眼，并发现收到的消息里头像被气泡盖住一条边。设计细节和色值见 [02 设计规范](02-design-system.md) 第 4.1、4.2 节。

- **调研结论**：中性色与强调色应取相近色相（Radix Colors：暖灰配黄、琥珀、橙、棕，冷灰才配蓝）；深色底上的高饱和色会产生视觉振动、使眼睛疲劳（Material Design 深色主题规范）；微信、WhatsApp、Telegram 的气泡都是淡彩或低饱和的深色，没有一家用满色度的实底；纸白配青绿有 Perplexity 和青绿山水两个先例。原来的蓝（#0066CC / #0A6FE0）接近 sRGB 的满色度。
- **决定**：九种强调色按同一条 OKLCH 规则重新生成（实底明度约 0.5、色度约为该色相上限的一半），只差色相、不差响度；新增"青"。维护者把九种在界面里逐一看过后，默认定为蓝（墨水蓝 #3C61A7 / #4167AD）。"提示"状态色用同一种蓝；强调色实底下的彩色投影减半；设置里分区图标的色块降低色度。存储的键没有改名，各设备保持原来的选择。
- **没有采用**：把自己的气泡改成"淡彩底配深色字"（微信、WhatsApp 的做法）。它要改气泡内链接、引用、文件卡和提及的整套配色，这一轮只调颜色。
- **气泡尾巴**：原先用一块底色去"挖"出尾巴，那块底色宽 10px，盖住了 8px 外的头像右缘。改为气泡该侧下角取直角、角外接一片用 `clip-path` 裁出的同色尾巴，不再有任何盖在别处的色块。
- **消息旁的时刻**：淡入，离开时立即消失。此前淡出的 0.14 秒里，刚打开的菜单后面会留着半透明的文字，无障碍检查在这一瞬间扫到过一次。
- **测试的一处纠正**：`e2e/a11y.spec.ts` 的"浅色"一轮此前只设置了系统配色偏好，而默认主题已改为深色，所以它实际检查的仍是深色主题。现在按成员选择主题的方式显式设置，浅色一轮才真正检查米白主题。
- **基线与素材**：Storybook 截图基线 148 张重新生成；README 与产品导览的中英文截图和动图重拍。
- **本地验证**（WSL，未经 CI）：`bun run check` 通过（后端与脚本 703 项、前端 770 项、对比度 2898 组、文案 1037 条）；Chromium 端到端 6 个文件（外壳、两个无障碍文件、聊天场景、助手场景、资料卡）45 项通过；官方镜像内视觉回归重新生成基线后再比对一遍，154 项通过。其余端到端、WebKit、Firefox、性能和媒体浏览器链没有在这次改动之后重跑。
